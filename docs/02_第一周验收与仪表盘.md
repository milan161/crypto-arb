## 一、30 分钟验收：数据怎么说

运行命令：

```powershell
python src\core\day03_scanner.py --minutes 30
```

09:23 到 09:53，共 116 轮，每轮约 15.5 秒（取 15 次报价约 5.5 秒 + 间隔 10 秒），**0 次重试、0 次取价失败**。明细在 `logs\scanner_20261124.csv`。

| 交易对 | 平均毛价差 | 最大毛价差 | 毛价差为正的轮数 | 最好的净价差 |
|---|---|---|---|---|
| BTC/USDT | 0.014% | 0.050% | 116 / 116 | −0.350% |
| ETH/USDT | 0.018% | 0.111% | 116 / 116 | −0.289% |
| SOL/USDT | 0.009% | 0.097% | 52 / 116 | −0.303% |
| DOGE/USDT | 0.007% | 0.088% | 37 / 116 | −0.312% |
| XRP/USDT | 0.007% | 0.115% | 50 / 116 | −0.285% |

成本（两边 taker 费 + 0.05% 滑点缓冲）一直是 0.40%。

### 四个观察

**① 580 个数据点，净价差全部为负。** 30 分钟里最大的一次毛价差是 XRP 的 0.115%，还不到成本的三分之一。主流币跨所现货搬砖这条路，用自己的数据确认了不通。

**② BTC、ETH 每一轮都是正毛价差。** 不是噪声，而是一个稳定的小价差，方向基本固定。这类价差往往来自各家的费率、提币成本、用户结构不同。它一直存在，恰恰说明这些差异本身就是成本，吃不掉。

**③ 09:50:06 这一轮，BTC 和 ETH 同时出现最大值。** 大概率是那一刻某家报价瞬间跳动或更新慢了。这种"瞬间价差"是专业做市商靠速度去抢的，我们不和他们拼。

**④ 小币价差一半正、一半负。** SOL 反复出现 0.0138%，XRP 出现 ±0.0105%，DOGE 出现 ±0.0175%，都正好是**一个 tick**：

| 币 | 价格约 | 最小变动 | 一个 tick 占比 |
|---|---|---|---|
| SOL | 72.6 | 0.01 | 0.0138% |
| XRP | 0.94 | 0.0001 | 0.0105% |
| DOGE | 0.057 | 0.00001 | 0.0175% |

也就是说，三家之间的价差大多只有 0～1 个 tick，基本是报价精度带来的噪声。

**思考题：** 如果 ETH 的毛价差稳定在 0.018%，手续费要降到多少，这个价差才"能做"？现实中谁能拿到这样的费率？

## 二、网页仪表盘

### 1. 为什么做

命令行每 15 秒刷一屏，3 所 × 5 对的数字很难看清。做成网页之后：表格原地刷新，净价差正负一眼看出，还能看走势。后面资金费率的机会清单也会放进来。

### 2. 技术选型

| 部分 | 技术 | 说明 |
|---|---|---|
| 后端 | FastAPI + uvicorn | 后台线程循环扫描，直接复用 `day03_scanner.py` 的函数，计算逻辑不变 |
| 前端 | Vue 3 + Vite + Naive UI + ECharts | 每 3 秒向后端取一次数据 |
| 启动 | `start_dashboard.bat` | 检查端口 → 装依赖（只在第一次）→ 开后端 → 开前端 → 打开浏览器 |

### 3. 怎么用

1. 确认代理节点能连上交易所（见 `01_价差扫描器.md` 的 curl 测速）
2. 双击程序根目录的 `start_dashboard.bat`
3. 第一次会自动安装 fastapi、uvicorn，并执行 `npm install`，大约 1～3 分钟
4. 浏览器打开 `http://localhost:5185`
5. 后端初始化三家交易所约 20 秒，这段时间显示 0 轮、No Data 是正常的，稍等刷新即可
6. 停止：关掉 "crypto-arb Backend" 和 "crypto-arb Frontend" 两个黑窗口

需要提前装好 **Node.js LTS**（前端要用 npm）。

### 4. 页面上有什么

- 右上角：每家交易所是否在线
- 四张卡片：已运行时长、扫描轮数、每轮耗时、取价失败次数
- 价差表：每个交易对显示净价差最高的方向；净价差为正标绿、为负标红；还有本次运行以来的最大毛价差、正毛价差占比
- 走势图：点表格某一行，画出它的毛价差和净价差曲线（保留约 3 小时）
- 明细同时写入 `logs\dashboard_日期.csv`

### 5. 端口：今天踩的坑

一台电脑上跑着好几个程序时，端口很容易撞车。我们的处理办法：

- **端口写进 `.env`**，不写死在代码里：
  ```ini
  DASH_BACKEND_PORT=8105
  DASH_FRONTEND_PORT=5185
  ```
  后端、前端、启动脚本都从这里读。端口冲突了，只改 `.env`。
- **启动脚本绝不关掉别的程序。** 发现端口被占，就停下来，告诉你是哪个程序（进程名 + PID）占着，由你决定改端口还是关掉它。
- **前端开了 `strictPort`。** 端口被占直接报错，不会悄悄换一个端口让你找不到页面。

还有一个小坑：最初把端口检查写成 bat 里的一长行 PowerShell 命令，`$`、引号被 cmd 解析坏了，脚本只显示"请按任意键继续"，看不到任何报错。后来把检查拆成独立的 `check_ports.ps1` 才解决。**bat 里不要塞复杂的 PowerShell 一行命令，单独写成 .ps1 文件更可靠。**

## 三、目录整理：仓库根 = `src/`

```
crypto/                      程序根（不是 git 仓库）
├── src/                     ← git 仓库根，只有这里上传 GitHub
│   ├── core/                config.py、day01~03 扫描器
│   ├── backend/app.py       仪表盘后端
│   ├── frontend/            仪表盘前端
│   ├── requirements.txt
│   ├── .env.example         配置模板
│   └── .gitignore
├── docs/  data/  logs/  学习计划/
├── .env                     本机密钥、代理、端口（不上传）
├── start.bat / start.ps1    打开开发环境
├── start_dashboard.bat      启动仪表盘
└── check_ports.ps1          端口检查
```

为什么这样分：

- **第一道防线是物理隔离。** 密钥、数据、日志根本不在仓库目录里，`git add .` 也不会带上它们。
- `.gitignore` 是第二道防线，额外忽略 `*.md`、`docs/`、`*.db`、`node_modules/` 等。
- `config.py` 自动判断上一级目录是不是叫 `src`，算出程序根，`data/`、`logs/`、`.env` 一律从程序根拼路径，不写死成 `src/data`。

运行命令随之变成：

```powershell
python src\core\day01_ticker.py okx BTC/USDT
python src\core\day03_scanner.py --once
```

小伙伴克隆仓库后得到的是 `src/` 的内容：放进自己的 `crypto\src\`，复制 `src\.env.example` 为程序根的 `.env` 并填好代理，就能跑。
