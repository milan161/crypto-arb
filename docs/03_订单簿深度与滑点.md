# 03 订单簿深度与滑点（第 2 周 · 第 1 步）

> 日期：2026-11-28
> 对应源码：`src/core/day04_depth.py`
> 上一篇：`02_第一周验收与仪表盘.md`

第一周的扫描器只看每个交易所的**第一档** bid / ask，滑点缓冲 0.05% 也是先拍脑袋定的。今天用真实的订单簿数据来检验：这个数靠不靠谱？

---

## 一、为什么要看深度

第一档往往只挂了很少的量。下单金额一大，就会吃到第二档、第三档，**成交均价比第一档更差，差出来的部分就是滑点**。

举个手工构造的例子：卖单簿第一档 100.0 元，只挂了 500 元的量；第二档 100.5 元；第三档 101.0 元。

| 买入金额 | 成交均价 | 吃到几档 | 滑点 |
|---|---|---|---|
| 300 | 100.00 | 1 档 | 0% |
| 1,000 | 100.25 | 2 档 | 0.25% |
| 3,000 | 100.66 | 3 档 | 0.66% |

同一个订单簿，下单量越大，成交均价越差。

## 二、程序怎么算

```powershell
python src\core\day04_depth.py                         # 默认：3 家交易所 × 5 个币 × 1000 与 10000 USDT
python src\core\day04_depth.py --notional 500 5000     # 自己指定金额
python src\core\day04_depth.py --symbols BTC/USDT DOGE/USDT --notional 10000
```

对每家交易所、每个币，取订单簿前 20 档，模拟"买入 / 卖出 N 个 USDT"：沿着订单簿一档一档吃，直到花完。算出成交均价、吃到几档、前 20 档够不够。明细写入 `logs\depth_日期.csv`。

**滑点的计算口径：**

```
买入滑点 =（成交均价 − 第一档卖价）÷ 第一档卖价
卖出滑点 =（第一档买价 − 成交均价）÷ 第一档买价
```

正数表示吃亏。

## 三、实测结果

时间：2026-11-28 16:10，okx / gate / bitget，BTC、ETH、SOL、DOGE、XRP，每笔 1000 与 10000 USDT，买卖两个方向，共 60 行。

| 发现 | 数据 |
|---|---|
| 60 行里滑点超过 0.05% 的 | **0 行**（最大 0.0423%） |
| 滑点最大的三行 | gate 卖 XRP 1 万：0.0423%（吃 7 档）；gate 卖 DOGE 1 万：0.0377%（吃 4 档）；gate 买 SOL 1 万：0.0302%（吃 4 档） |
| 1000 USDT | 绝大多数行是 0.0000%，最大是 gate 买 DOGE 的 0.0136% |
| BTC 1 万 USDT | 几乎没有滑点（最大是 bitget 买入 0.0032%，吃 5 档） |
| 深度够不够 | 60 行全部"够" |

### 四点观察

**① 0.05% 的滑点缓冲，对 1 万 USDT 以内的单子够用，甚至略保守。**
但这只是一个时间点的快照。行情剧烈波动时订单簿会变薄，需要多采几个时间点才能下结论。

**② 滑点和成本比，不是一个量级。**
最差的 0.0423% 也只占总成本 0.40% 的约十分之一，成本的大头是手续费。**想让套利有空间，应该先从降手续费入手，而不是优化滑点。**

**③ 交易所之间深度差别明显。**
gate 的订单簿最薄：同样 1 万 USDT，ETH 要吃 11～12 档，XRP 卖出要吃 7 档。bitget、okx 的前几档厚得多。gate 的 taker 费（0.20%）在三家里最高，深度还最薄，做吃单最不划算。

**④ 买入和卖出不对称。**
okx DOGE 1 万 USDT：买入滑点 0.0192%，卖出 0.0041%。同一个币、同一家交易所，买卖两侧的挂单厚度可以差几倍，所以买和卖要分开算。

## 四、一笔账：为什么"看起来有价差"，扣完成本是亏的

用第一周 30 分钟里最好的一次毛价差（XRP，0.115%），单笔 10,000 USDT：

| 项目 | 比例 | 金额 |
|---|---|---|
| 账面价差赚到 | +0.115% | **+11.5 USDT** |
| 买入所 taker 费（okx） | −0.15% | −15 USDT |
| 卖出所 taker 费（gate） | −0.20% | −20 USDT |
| 滑点缓冲 | −0.05% | −5 USDT |
| **合计** | **−0.285%** | **−28.5 USDT** |

账面赚 11.5，成交瞬间先付出 40，每做一次净亏 28.5。如果毛价差达到 0.5%，扣完是 +0.10%，勉强为正，但还要面对下面几个现实：

1. 价差存在的时间极短，你看到的是几秒前的报价；
2. 两笔单不是同时成交的，先成交一边、另一边价格动了，就是**单腿风险**；
3. 深度不够，实际滑点可能远大于 0.05%；
4. 两家交易所都要备好币和钱，转账又有成本和时间。

## 五、今天踩的坑：每家交易所的返回格式不完全一样

第一次运行时报错 `ValueError: too many values to unpack (expected 2)`。原因：OKX 的订单簿每一档除了 `[价格, 数量]`，后面还带着额外字段，而代码写的是 `for price, amount in levels`，数量对不上。

修复：不要直接解包，用下标取前两个值。

```python
for lv in levels:
    price, amount = lv[0], lv[1]
```

**ccxt 统一的是字段名，不保证每一项的长度都一样。** 处理交易所数据时，下标取值比解包更稳。自己写的函数用手工构造的数据测试，也要想一想"真实数据会不会多出一些东西"。

## 六、作业

**手算题：** okx 买入 DOGE 1 万 USDT，第一档价 0.05685，成交均价 0.0568609，吃了 3 档。滑点是多少？

两种分母算法：

```
除以第一档价：(0.0568609 − 0.05685) ÷ 0.05685   = 0.01917%（程序口径，显示为 0.0192%）
除以成交均价：(0.0568609 − 0.05685) ÷ 0.0568609 = 0.01917%
```

两种结果只在小数点后第五位有差别，可以忽略，但要知道程序用的是前一种。

**思考题：**
1. 毛价差 0.05%，买一边滑点 0.03%、卖一边滑点 0.03%，这笔单还有机会吗？
2. 下单量是不是越小越好？最小下单量又会成为什么样的限制？
3. 为什么 gate 的卖出滑点普遍比买入大？这和它的订单簿结构有什么关系？
